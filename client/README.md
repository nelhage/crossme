# CrossMe client

The CrossMe web client: React + TypeScript, built with [Vite][vite]. It talks
to the Go server over [gRPC-web][grpc-web], via the envoy proxy configured in
`../proxy/envoy.yaml`.

[vite]: https://vite.dev/
[grpc-web]: https://github.com/grpc/grpc-web

## Scripts

| Command             | What it does                                                        |
| ------------------- | ------------------------------------------------------------------- |
| `npm run dev`       | Dev server on http://localhost:3000, proxying `/api` to envoy       |
| `npm run build`     | Type-check, then build a production bundle into `dist/`             |
| `npm run preview`   | Serve the contents of `dist/` locally                               |
| `npm test`          | Run the [Vitest][vitest] suite once (`npm run test:watch` to watch) |
| `npm run typecheck` | `tsc --noEmit`                                                      |
| `npm run lint`      | ESLint                                                              |
| `npm run format`    | Rewrite files with Prettier (`format:check` to only check)          |

[vitest]: https://vitest.dev/

`../scripts/start-servers` brings up the dev server, envoy, and the Go server
together in a tmux session.

## Generated protobuf code

`src/pb/` is generated by `../scripts/gen-proto` and checked in; don't edit it
by hand. Regenerating it needs `protoc` plus the `protoc-gen-js` and
`protoc-gen-grpc-web` plugins on `$PATH` (see that script for details).

`protoc-gen-js` can only emit CommonJS, so those files are CJS modules inside an
otherwise-ESM source tree. The production bundler handles that natively; the dev
server and Vitest go through `vite-plugin-protobuf-cjs.ts`, which converts them.
